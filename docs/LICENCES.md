# Sentinel Gujarat — open-source components and licences

The portal states: *"All solutions should use open-source technologies."* Every runtime component of Sentinel Gujarat `1.0.0-phase1` is open source, listed below with its licence and link. No proprietary VMS, vendor SDK or cloud AI service is used anywhere in the demo path. Items marked **verify** must have the licence text re-checked at the linked page before the PDF export (licence terms can change between versions); items marked **not part of the solution** are platform dependencies or development tools that are not distributed with, or required at runtime by, the product.

Versions are the ones pinned in `frontend/package.json`, `backend/requirements.txt`, `anpr/requirements.txt` and `deploy/docker-compose.yml` at tag `v1.0-phase1`; the deploy builder records the MediaMTX image digest here after the final build.

## Notes

**A — react-leaflet (removed).** Since v3, react-leaflet is published under the Hippocratic License 2.1, a source-available licence with ethical-use restrictions that the OSI has not approved. Because the portal asks for open-source technologies, the wrapper was **replaced before submission** by in-repo React bindings (`frontend/src/components/leaflet.tsx`, MIT) that implement only the surface the pages use on top of Leaflet (BSD-2-Clause). `react-leaflet` is not in `frontend/package.json` and not in the built bundle; the only Hippocratic-licensed code ever considered is therefore absent from the solution.

**B — GPL components (ffmpeg builds, PostGIS).** ffmpeg and PostGIS are invoked as separate processes/services over a command line, RTSP or SQL; no Sentinel Gujarat code links against them. GPL obligations therefore attach only to redistributing those binaries themselves (which we do not modify and obtain from their public images/packages), not to our source, which is released under MIT. Both are OSI-approved open-source licences and satisfy the portal requirement.

**C — NVIDIA runtime.** GPU acceleration (NVDEC/NVENC, CUDA) depends on NVIDIA's proprietary driver and redistributable runtime libraries, exactly as any GPU-accelerated open-source stack does. The solution's own code and every application-level component remain open source, and the `cpu` profile runs the complete product with no NVIDIA software at all.

**D — AGPL fallback (Ultralytics).** The primary plate detector is the Apache/MIT ONNX model above, run with onnxruntime. The Ultralytics YOLOv8 licence-plate model is AGPL-3.0; it is **not installed** in the default images and is used only if the primary model cannot be obtained or fails on the sandbox footage, in which case (i) the README and this file state it, (ii) the worker source is already published under MIT, satisfying AGPL's network-use source-availability requirement for the combined work. A contour-based fallback detector (OpenCV, Apache-2.0) exists in the worker as the first fallback.

**E — Face recognition weights.** If F1 (FRS on watchlisted persons) is demonstrated, the InsightFace `buffalo_s` weights are research-only; the demo would declare it and a production FRS would need commercially licensed or state-trained models. F1 is roadmap in `1.0.0-phase1`.

**Our own code.** Everything in the `sentinel-gujarat` repository authored by Dynatech Consultancy is released under the MIT License — `LICENSE` at the repository root, `SPDX-License-Identifier: MIT`, Copyright 2026 Dynatech Consultancy. `frontend/package.json` carries the same `"license": "MIT"` field (checked in the consistency pass, `submission-checklist.md` §3.5: `grep '"license"' frontend/package.json` must print `MIT`). If the organiser's answer to the IP-ownership question (ORGANISER-EMAIL.md Q3) requires a different arrangement, `LICENSE`, `package.json` and this paragraph change together.
