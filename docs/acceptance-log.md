### Defects found against the real streams and fixed (in the working tree, built into the running images)

1. `StreamPlayer` gave up after a fixed 5 s ICE budget while the relay was still pulling a cold sandbox source (4–40 s): the WHEP offer / HLS manifest now get a 45 s budget when `/streams/{id}` says `ready=false`, the ICE budget starts after the answer, and a playing session that loses its transport restarts the WebRTC → HLS → snapshot chain.
2. 11 cameras send B-frame H.264, which MediaMTX refuses over WebRTC and whose HLS muxer dies (`too many reordered frames`): the probe records `has_b_frames`, `needs_transcode` routes them to `cam_<id>_h264` like H.265, `/streams/{id}` adds `transcoded` / `whep_supported` / `preferred_mode`, tile caption "H.264 (re-encoded)".
3. Five 1080p `veryfast` encoders saturated MediaMTX's 4-core cap (465 % CPU, `runOnDemand` start timeouts): the CPU transcode is now 720p `ultrafast` 1200k (`CONTRACT.md` amendment).
