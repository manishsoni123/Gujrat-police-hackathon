# media/ - video inputs (read-only inside the containers, mounted at /media)

| Directory | Content | Committed? |
|---|---|---|
| `synthetic/` | `cam_1.mp4 … cam_8.mp4` (1280×720, 10 fps, 90 s loops; cam_8 is H.265) and `plates.json` (ground truth) generated by `scripts/make_synthetic_videos.py` | only `plates.json` |
| `own/` | `own_gate.mp4` – the team's phone video of the office gate (Video 1). MediaMTX serves it as `rtsp://mediamtx:8554/own_gate`; when the file is absent the path falls back to `synthetic/cam_1.mp4` | no |
| `fallback/` | `<id>.mp4` – 10-minute recordings of chosen organiser sandbox cameras (`ffmpeg -rtsp_transport tcp -i rtsp://<host>:8554/stream/<id> -c copy -t 600 fallback/<id>.mp4`), served as `fallback_<id>` paths when enabled in `deploy/mediamtx.yml` | no |

Regenerate the synthetic set (deterministic for `SYNTH_SEED=42`, about 2–3 minutes on a laptop CPU):

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env --project-directory . --profile tools run --rm synth
# or: make synthetic
```

MediaMTX (`deploy/mediamtx.yml`) publishes `synthetic/cam_<n>.mp4` as `stream/<n>` – the same URL
shape as the organiser sandbox – with `ffmpeg -re -stream_loop -1 … -c copy`, so the 90 s loop
restarts forever and the ANPR worker sees the same discontinuities it will see on the real feeds.
The publisher waits until the file exists, so MediaMTX may be started before the generator.
